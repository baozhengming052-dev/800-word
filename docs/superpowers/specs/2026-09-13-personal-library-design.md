# 手动添加新词与练习题：功能方案

日期：2026-09-13。

状态：用户已确认功能范围和本设计，并要求继续实现。以下为本次实现与验收依据，不表示尚未验证的功能已经完成。

## 1. 本次要解决的问题

遇到内置资料没有的词，用户可以在手机或 iPad 上手动录入，并为新词或已有词补充题目。自建内容接入现有搜索、词卡、刷题、错词和笔记，同时保留“我的添加”筛选。无需联网、账号或电脑录入。

不直接修改安装包中的原始词库。采用“内置资料只读、个人内容独立保存、学习时统一展示”的方式，而不是另建一套与现有错词系统无关的练习页面。

已有约束继续有效：iPhone 14 Pro Max 和 iPad Pro 2021、系统16.5、TrollStore 安装、iPad 横屏；用户通过 GitHub Desktop 上传并用 GitHub Actions 构建，不需要本机 Xcode。不代替用户提交、创建 Tag 或推送。

## 2. 用户看到的功能

### 2.1 添加与管理新词

- 词库提供“＋ 添加新词”，保留现有分类、状态和排序，再增加“全部 / 我的添加”来源筛选。
- 必填：词语、释义。可选：拼音、分类、例句、重点与辨析、个人笔记。分类未填时归入“自建词”。
- 保存后立即进入词条详情，能搜索、收藏、标记掌握程度、修改错误次数和参与词卡复习。
- 本机存在相同词形时先显示已有词，允许打开它补题或补笔记，不直接覆盖内置资料，也不默认重复创建。
- 自建词显示“手动添加”，不伪造 PDF 页码、原文或真题出处。保留原有“释义 → 个人笔记 → 解析/辨析 → 我的学习”的详情顺序。
- 支持编辑自建词内容；内置词的原文仍只读。个人笔记沿用现有笔记及修订历史，不另外建立一份互相不同步的笔记字段。
- 不提供永久删除按钮；使用“归档 / 恢复”，从日常学习中移除但保留词条、题目引用和历史记录。

### 2.2 手动录入题目

- 刷题页面提供“我的题目”管理入口和“添加题目”。词条详情也有“给这个词添加题目”，自动选中当前词。
- 必填：题干、四个 A—D 选项、一个正确答案、解析、至少一个关联词。正确答案初始不预选，必须由用户明确选择。
- 关联词可搜索并多选，包含内置词和自建词；未保存的新词先完成保存，再返回关联选择，题目草稿保留。
- 可选填写来源说明，例如考试名称、年份或个人出处。题目统一明确标注“手动录入”，不会因为填了考试名称就宣称已经核实为官方真题。
- 允许保存后继续编辑或归档；管理页区分正常题目与已归档题目，能预览完整内容。
- 题目预览属于录入管理，不是正式答题。练习页面提交前始终不显示正确答案、解析、相关词释义或个人笔记，不增加首字、字数等答案提示。

### 2.3 接入现有练习

- 自建题归入“手动录入”题型，可单独练习；“全部题型”也包含它，不把手动录入混标为原有真题或模拟题。
- 随机练习、分类练习、错词专项都能选择自建题；仍保留现有每组题数设置和错词优先顺序。
- 答错时，题目关联的词进入现有错误统计、历史和复习安排；一次提交只产生一次答题记录。
- 自建词只有释义、尚未录题时可以词卡复习，但不自动捏造题目。详情说明暂无关联题，并提供添加入口。
- 归档题不再进入新的练习组。已归档词不进入日常词卡与提醒；新的练习只按未归档的关联词进行筛选。历史回顾依然能看到归档内容。
- 已开始的一组练习固定本组题目版本；过程中发生编辑、归档或同步，不替换正在作答的题目，也不丢失已选答案。

## 3. 输入与界面规则

- 新录入的词题字段保存前去除首尾空白，保留内部换行；纯空白不算有效内容。个人笔记继续沿用既有编辑和保存规则，不改写原笔记格式。
- 词语限80个字符，拼音/分类各限100个字符；题干、释义、解析、例句、辨析及来源说明各限10000个字符；每个选项限2000个字符。限制在界面中提示，超过上限不静默截断。
- 这些新字段限制不改变既有个人笔记的100000字节上限。单个个人内容修订编码后最多256 KB，同时受整个备份大小上限约束；所有限制在保存和导入时共同验证。
- 题目必须有四个非空且不重复的选项，答案必须在 A—D 中，关联词不能重复或缺失。来源说明不是获取远程内容的入口。
- 重复点击保存不得重复创建。保存失败时保留编辑内容并说明原因；只有成功落盘才关闭编辑器。
- 有未保存修改时，关闭编辑器先确认是否放弃。旋转或切换 iPad 宽窄布局时保留当前会话草稿；本版不承诺进程被系统终止后的未保存草稿恢复。
- iPhone 使用适合单栏的表单；iPad 使用限宽编辑窗口，字段可滚动，键盘不挡住保存操作。风格沿用系统深浅色和现有强调色，不新增第三方界面依赖。

## 4. 数据结构与历史保护

### 4.1 稳定身份与不可变修订

自建词有稳定的词条 ID。自建题有稳定的题目条目 ID，以及每次内容修订独立的版本 ID。编辑标题、释义或题目时，不把旧身份当作新记录重新累计。

个人内容采用不可变修订记录保存，包含记录 ID、条目 ID、父修订 ID 集合、内容和时间。保存、编辑、归档、恢复及同步冲突处理都追加新记录，不原地改写旧记录。父修订关系用于判断是否为真正的双方独立修改，不能只用设备时间决定覆盖谁。

现有学习事件 ID 保持不变。将个人内容修订纳入新版学习快照，使词、题和学习事件一起原子保存、导出与同步，避免“同步了答题记录，却没有它对应的题目”。新增事件种类须有专门解码与验证规则，不能将未经验证的文本直接当作模型载入。

### 4.2 题目版本与计分

- 自建题的每个内容版本保留完整题干、选项、正确答案、解析和关联词 ID。
- 新答题引用本次出题时的版本 ID；历史回顾、对错统计和错词归属也使用这个版本，不查找后来编辑后的答案。
- 内置题 ID、原有答题事件和计分规则保持兼容；不重写已有历史。
- 自建题使用词条 ID 建立关联，显示时再取词形，防止词语改名后关联失效。内置题原有字符串关联在内置目录中解析，不依赖任意同名自建词。
- 归档或恢复是条目状态变化，不改写过去的答案或计分。已经开始的练习仍按冻结版本记录；其历史必须可读。

### 4.3 内容目录与学习逻辑的边界

- 个人内容层：验证修订、构建当前词题目录、保存历史版本、识别内容冲突和归档状态。
- 学习层：在有效目录上计算错误次数、掌握状态、收藏、笔记和复习计划；不负责解析任意录入文本。
- 数据管理层：统一组织目录、事件、搜索索引、持久化和备份；保存后统一刷新视图，禁止仅在界面数组中临时追加内容。
- 同步层：继续采用已有的加密附近连接及双方确认流程，扩展传输内容和预览，不另建网络服务。

## 5. 本地保存、备份与升级

- 新快照使用独立的版本标识3，统一保存个人内容和学习记录。使用 `study-v3.json` 及上一份有效备份，不覆盖原 `study-v2.json`。
- 首次升级时，若不存在 v3 文件，读取并验证旧 v2 记录，原样保留事件 ID，再原子写入 v3；失败则保留旧文件并暂停写入，不能表现为空白学习记录后继续覆盖。
- 已存在但损坏的 v3 文件，先保留损坏文件，尝试上一份有效 v3 备份；都不可用时提示导入备份，不静默退回过期 v2 状态。
- 新版支持导入 v2 备份及完整 v3 备份；v2 备份没有个人内容，导入时不能清空本机已有的自建词题。未来未知版本明确拒绝。
- v3 导入先构建并验证“内置资料＋导入的个人内容”的完整目录，再验证学习事件引用。外来新词不能因为尚未存在于本机就被旧验证规则误判。
- 保留现有20 MB总大小上限和100000条记录上限，个人修订计入总量；新增内容与合并后的最终文件都必须满足上限。超限或数据无效时不修改本机状态。
- 验证唯一编号、父修订存在与无环、题词引用、正确答案范围、文本上限、合法时间以及归档状态，防止损坏备份造成崩溃或改写历史。
- 导出失败时不得生成空白“成功备份”。新版数据不承诺可供旧版 App 读取，升级后不建议降级安装。

## 6. 附近同步与冲突处理

- 保持内置资料指纹校验，指纹只针对随包内置资料，不把用户新增词题算进去；两台个人内容不同是正常待同步状态，不能因此拒绝连接。
- 明确区分新的同步数据能力，旧版与新版不交换不兼容快照，提示两台先升级。不能让旧版忽略自建内容却接受其学习记录。
- 合并时按不可变记录 ID 去重；同 ID 不同内容拒绝。重复同步不会增加同一条题目、词条、笔记或答题记录。
- 一方的修订明确继承另一方时采用后继版本；双方基于相同旧版本独立编辑时，预览两份内容并由用户选择。未选中的版本保留在历史中，不静默丢弃。
- 选择结果通过新的合并修订保存，其父引用覆盖双方待处理分支；再次同步相同历史时不重复弹出已经解决的内容冲突。先处理内容、归档和同名冲突，再核对学习记录冲突，最终验证完整快照。
- 归档与编辑发生冲突时同样需要确认；不能因另一台旧记录到达就自动恢复已经归档的内容。
- 双方独立创建了同名但不同 ID 的词时，提示选择哪一条作为后续学习的活跃词；另一条归档并保留原学习历史，不直接把两条词的错误总数相加。历史题目仍引用各自原 ID。
- 同名判断使用规范化后的词形；本机新增/改名和同步后的目录都检查冲突，不允许底层名称字典因重复键崩溃。需要再次使用归档词时也先处理同名冲突。
- 内置词不能被同名自建词覆盖或归档；如载入或导入时发现此类重名，保留自建条目的身份与历史，提示对自建条目改名或归档。同名属于可处理的内容冲突，不当作损坏文件导致整库无法打开。
- 原有笔记、手动错误次数冲突选择继续保留。新增题词数量、编辑/归档变化和相关冲突都列入双方预览，不能只展示学习事件条数。
- 预览后任何本机学习或内容修改都会使旧方案失效，必须重新预览；最终落盘必须包含原本机的全部不可变记录。
- 沿用发送方案、双方确认、断线重试和校验摘要，不以单方保存冒充双方同步完成。

## 7. 本版不增加的功能

- 不接入 API、拍题识别、AI 自动出题或解析，也不抓取联网题库。
- 不编辑原始 PDF 或内置词题，不把手动输入冒充原资料或经核实的真题。
- 不增加云账号、iCloud、电脑服务器或扫码连接。
- 不做批量表格导入、富文本图片附件、永久删除与历史记录清空。
- 不改变现有 Bundle Identifier、安装方式及 Tag 驱动的 GitHub IPA 发布方式；新增工程文件须加入现有构建和测试流程。

## 8. 验收标准

### 数据与逻辑测试

1. 添加新词/题后重建状态、重新解码文件，内容和学习记录一致；取消或保存失败不留下半条数据。
2. 缺字段、纯空白、重复选项、缺少答案、无效词引用、重复编号、修订环和超限内容被拒绝，原记录不变。
3. 新词可搜索、分类、收藏、写笔记、修改错误次数和参与词卡；自建题可随机、分类、错词练习并正确记录关联词。
4. 答完题再改正确答案、选项或关联词，原成绩、历史解析和原错词归属不变；再次出题采用新版本。
5. 词改名不丢题目关联；归档不清空历史，恢复正常；归档内容不进入新的日常练习与提醒。
6. 升级加载 v2 不丢事件；v2 导入不删个人内容；v3 备份往返、损坏恢复、未知版本拒绝和原子保存失败处理正确。
7. 两台分别新增、单方编辑、双方编辑、归档冲突、同名创建、重复同步及断线重试均遵守合并规则；缺少被引用题词时不保存不完整快照。
8. 预览后产生新答题、新词或题目编辑时，拒绝旧方案覆盖；保留既有手动次数和笔记冲突行为。

### 界面与设备验收

1. iPhone 和 iPad 的录入、关联词选择、搜索/筛选、管理与归档流程可完成，长中文和键盘场景可用。
2. iPad 横屏/竖屏/窄窗口切换不丢本次编辑草稿；词条详情笔记区域仍在上方。
3. 自建题提交前不泄露答案；作答中旋转、编辑或同步不替换本组冻结版本，重复点提交不重复计数。
4. 两台16.5设备使用新版进行离线附近同步，确认新增内容、冲突预览及断线后重试结果一致。

Windows 本地完成可执行的数据/工程检查和回归测试；原生 Swift 测试与 iOS 编译由 GitHub 的 macOS 环境执行，最终安装、界面及双机连接需真机验收。不得把静态检查通过表述为已经构建 IPA 或真机验收通过。

## 9. 开发前确认点

功能范围依据用户已确认的聊天方案。此文补充了安全保存、题目版本、同名词处理及旧数据兼容规则。用户确认本文件后再制定实现计划和编写功能代码；本文不授权代替用户上传或发布。
